## 1. 这是什么

把**多个** WorkBuddy / CodeBuddy / TraeWork 账号，合并成一个 **OpenAI 兼容接口**，并且**每天自动签到**帮你领额度。

**它能帮你做什么**

- 多个账号的额度**合起来用**，不用手动切换
- 每天到点**自动签到**，不用记着去点
- 面板上看每个账号**还剩多少积分**、签到成没成功
- 自动刷新登录凭证、出错自动冷却，不用管

**它长什么样**

一个**右下角托盘图标**（绿色 W），单击就弹出管理面板。没有主窗口、不占任务栏。

## 2. 安装与启动

### 2.1 下载

从 [Releases](https://github.com/sddvcm/workbuddy-wild/releases) 下载最新的：

```
workbuddy-wild-windows-amd64-v0.4.0.zip
```

解压到**任意目录**（建议英文路径，如 `D:\workbuddy-wild\`）。

### 2.2 系统要求

- **Windows 10 21H2 或更高**
- 不需要装 Go / Python / Node / Docker —— **零依赖**

> 如果系统较旧，首次运行会自动安装 WebView2 运行时（需要联网）。

### 2.3 启动

双击 `workbuddy-wild.exe`。

首次运行会：

1. 自动生成 `config.json`（默认监听 `http://127.0.0.1:7863`）
2. 弹出提示框显示 **API 地址** —— 记下来，关掉即可
3. 右下角出现**绿色 W 托盘图标**

> ⚠️ 程序启动后**没有主窗口**，这是正常的。所有操作都在**托盘面板**里 —— 单击托盘图标打开。

> 如果之前没关干净，再次双击 exe 会提示"已在运行"，询问你打开面板还是退出。

## 3. 第一次配置：添加账号

### 3.1 添加 WorkBuddy / CodeBuddy 账号

1. 单击托盘图标打开面板
2. 左栏点 **「＋ WorkBuddy」**
3. 程序**自动打开无痕浏览器**，跳到登录页
4. 在浏览器里**正常登录**你的 WorkBuddy / CodeBuddy 账号
5. 登录成功后，程序**自动抓取凭证**、写入账号、并立刻签到一次

面板上会显示倒计时（5 分钟内完成登录）。如果浏览器没自动弹出：

- 点弹窗里的 **「复制链接」**，自己粘贴到浏览器打开

### 3.2 添加 TraeWork 账号

同上，点 **「＋ TraeWork」**。

> 两种账号可以**混着加**，互不影响。面板上 W 图标是 WorkBuddy，T 图标是 TraeWork。

### 3.3 加完账号后必须做一件事

**点一次「全部刷新」**（左栏底部）。

原因：积分是**缓存值**，刚加的账号积分显示为 0。不刷新的话，「优先积分」策略会因为所有账号都是 0 分而退化成随机挑。刷新后策略才能正常工作。

### 3.4 关于多账号与风控

- 同一台机器可以加多个账号，程序会**按策略轮换**
- 但**同一账号**不要在多台机器/多个客户端同时用，容易触发风控
- 程序内置自动冷却：某账号余额不足会冷却 12 小时，`429` 会冷却 60 秒

## 4. 把 AI 客户端接进来

任何支持 OpenAI 格式的客户端都能用：

```
Base URL : http://127.0.0.1:7863/v1
API Key  : WorkBuddy2API
```

> API Key 可以在面板右栏 **「API 监听」→ API-Key** 处点击修改。
> 如果只在本机用，留空也可以（不鉴权）。

### 4.1 模型名必须带平台前缀（重要）

| 平台 | 前缀 | 示例 |
|---|---|---|
| WorkBuddy / CodeBuddy | `workbuddy/` | `workbuddy/glm-5.2`、`workbuddy/deepseek-v4-pro` |
| TraeWork | `traework/` | `traework/glm-5.2`、`traework/kimi-k2.7-code` |

**不带前缀会返回 400 错误。**

### 4.2 查看完整模型列表

浏览器打开或命令行：

```
http://127.0.0.1:7863/v1/models
```

> 需要带 `Authorization: Bearer <你的API-Key>` 请求头（API-Key 为空则不需要）。
> 模型列表是**动态**从上游拉取的，缓存 1 小时。

### 4.3 pi 配置示例

```json
{
  "providers": {
    "workbuddy": {
      "type": "openai",
      "baseUrl": "http://127.0.0.1:7863/v1",
      "apiKey": "WorkBuddy2API",
      "models": ["workbuddy/glm-5.2", "workbuddy/deepseek-v4-pro"]
    }
  }
}
```

### 4.4 局域网/其他设备访问

默认只监听本机（`127.0.0.1`）。要让手机、其他电脑也能用：

1. 面板右栏 **「API 监听」** → 主机选 **`0.0.0.0`（全部）**
2. 立即生效（**不用重启**）
3. 其他设备用 `http://<这台电脑的IP>:7863/v1`

> ⚠️ **改成 `0.0.0.0` 后一定要把 API-Key 改掉！**
> 默认 Key 是公开的 `WorkBuddy2API`，不改的话局域网内任何人都能**白嫖你的额度**。
> 程序检测到"默认 Key + 对外监听"时会弹窗警告。

## 6. 积分策略怎么选

右栏最上面是 **「积分策略」** 下拉，改完**立即生效**，两个平台共用。

| 策略 | 什么时候用 | 怎么选号 |
|---|---|---|
| **优先积分**（默认） | 想让每个账号**均衡消耗** | 选剩余积分**最多**的账号。积分相同时按账号 ID 稳定排序 |
| **优先过期** | 有的账号**凭证快到期了** | 优先用**最快过期**的账号，避免到期浪费额度。没积分的账号跳过 |
| **负载均衡** | 想**平均分摊调用次数** | 按顺序**轮流**使用每个账号 |

**建议**：

- 一般情况用默认的**优先积分**就行
- 发现某个账号快过期、额度还没用完 → 临时切 **优先过期**
- 想避免单账号请求过多被限流 → 用 **负载均衡**

> 策略会记到 `config.json` 的 `strategy` 字段，重启后保持。

## 7. 看懂账号卡片

每个账号一张卡片，浮动显示当前状态：

```
┌─────────────────────────────────────────────┐
│ W  账号名            ● 调用中        1,240   │  ← 图标/名称/标识/积分
│    ✓ 签到 16:12 · 调用 16:14:03              │  ← 状态行
└─────────────────────────────────────────────┘
```

### 7.1 「正在调用」标识

| 标识 | 含义 |
|---|---|
| 🟢 **调用中**（绿色脉冲圆点） | **请求正在使用这个账号**（最近 5 秒内） |
| ○ **最近用过**（灰色） | 用过，但超过 5 秒了 |
| （无标识） | 还没被调用过 |

**正在调用的账号会自动排到列表最上面**，方便一眼看到。

> 说明：程序按"最近调用时间"判断，所以标识可能在请求结束后**保留最多 5 秒**才消失，这是正常的。

### 7.2 状态颜色

| 颜色 | 含义 |
|---|---|
| **绿色** | 正常 / 签到成功 |
| **橙色** | 冷却中（例如：余额不足，冷却 12 小时至 xx:xx） |
| **红色** | 已禁用（登录失效，**需要重新添加账号**） |
| **灰色** | 尚未签到 |

### 7.3 积分显示

- 显示的是**上次刷新时的积分**，不是实时值
- 想拿最新值 → 点 **「全部刷新」**，或单账号刷新
- **每次成功调用后**程序会更新，但签到/刷新是主要更新时机

### 7.4 删除账号

卡片右侧的**垃圾桶图标** → 弹确认框 → 确定后同时删除凭证文件。

## 8. 日常使用

| 想做什么 | 怎么做 |
|---|---|
| **马上签到所有账号** | 左栏 **「全部签到」** |
| **刷新所有积分** | 左栏 **「全部刷新」** |
| **改自动签到时间** | 右栏「自动签到」→ 改时间框（**改完立即生效**） |
| **加签到时间** | 点时间旁的 **＋**（最多 4 个） |
| **删签到时间** | 点时间块上的 **×** |
| **改监听地址/端口** | 右栏「API 监听」→ 改下拉/端口（**立即生效**） |
| **改 API-Key** | 点 API-Key 那个值 → 输入 → 回车或点别处保存 |
| **看日志** | 右栏「日志文件」→ 打开（用记事本） |
| **看版本/项目地址** | 右栏「关于软件」→ 查看 |
| **退出程序** | 右上角 ✕ 或底部「退出程序」（都会弹确认） |

> **自动签到默认时间**：每天 **09:00** 和 **21:00**。
> **token 保活**：每天 **22:00** 自动刷新凭证，防止掉登录。

## 9. 托盘图标操作

| 操作 | 效果 |
|---|---|
| **单击** | 打开管理面板 |
| **双击** | 打开管理面板 |
| **右击** | 打开管理面板 |
| **鼠标悬停** | 显示提示文字 |

> 三种点击都是**打开面板** —— 程序**没有**右键菜单，这是有意设计的（见开发文档 §4.6，原生菜单会导致托盘卡死）。

**关闭面板**：按 **Esc**、点右上角 **—**、或点面板外面。

> 关闭面板**不会退出程序**，只是隐藏。程序继续在后台跑（HTTP 服务 + 自动签到）。
> 想**真正退出** → 用面板里的「退出程序」。

## 10. 文件与目录

所有文件都在 **exe 所在目录**：

```
你的目录/
├── workbuddy-wild.exe        ← 主程序
├── config.json               ← 配置（首次运行自动生成）
├── auths/                    ← 账号凭证（已加密，别外传！）
│   ├── workbuddy-<uid>.json
│   └── trae-<uid>.json
└── data/
    ├── state-workbuddy.json  ← WorkBuddy 池状态（积分/签到/冷却）
    ├── state-traework.json   ← TraeWork 池状态
    ├── panel-pos.json        ← 面板位置记忆
    ├── app.log               ← 运行日志（超 5MB 自动轮转）
    └── webview/              ← WebView2 缓存
```

### 10.1 备份与迁移

**要备份**：整个目录里的 `config.json` + `auths/` + `data/state-*.json`

**换电脑**：
1. 拷贝 `config.json` + `auths/` + `data/state-*.json` 到新电脑同目录
2. 直接运行 exe

> ⚠️ **`auths/` 里的凭证用 Windows DPAPI 加密，只能在同一台电脑的同一用户下解密！**
> 换电脑后凭证**无法复用**，需要重新添加账号。（`config.json` 和 `state.json` 可以迁移）

### 10.2 日志

`data/app.log`，超过 5MB 自动转存为 `app.log.1`（覆盖旧备份）。

排查问题时应提供日志内容（**但注意日志里可能含账号 UID，分享前自行脱敏**）。

## 11. 开机自启

右栏 **「开机自启」** 开关，打开即可。

- 通过注册表 `Run` 键实现
- 自启时会带 `--autostart` 参数，**不弹**"已启动"提示，直接静默进托盘
- 关掉开关即取消

## 12. 常见问题

### Q1：双击 exe 没反应 / 没窗口？

**正常。**程序启动后只有**托盘图标**，没有主窗口。

- 看**右下角**托盘区（可能被折叠，点 `^` 展开）找绿色 **W** 图标
- 单击图标打开面板

### Q2：托盘图标找不到？

- 点任务栏右下角的 `^` 箭头，看折叠区
- 可以把它拖出来固定到任务栏
- 如果确实没有，看任务管理器里 `workbuddy-wild.exe` 是否在运行

### Q3：提示"面板已崩溃"或"面板不可用"？

WebView2 出问题了。**HTTP 服务和自动签到仍在正常跑**，只是面板打不开。

- **解决方法**：重启程序。或者先不管，API 照常能用
- 如果反复出现，试着重启电脑、更新 WebView2 运行时

### Q4：API 调用返回 400 `invalid_model`？

模型名**没带平台前缀**。要写 `workbuddy/glm-5.2`，不能只写 `glm-5.2`。

### Q5：API 调用返回 401？

API-Key 不对。检查客户端里填的 Key 是否和面板「API-Key」一致。

### Q6：API 调用返回 503 `no_healthy_account`？

所有账号都不可用（冷却中或已禁用）。

- 看面板账号卡片的状态
- 红色「已禁用」→ 需要**重新添加账号**（登录失效了）
- 橙色「冷却中」→ 等冷却结束，或点「全部签到」尝试恢复

### Q7：账号显示"已禁用"怎么办？

登录凭证彻底失效了（session dead）。只能：
1. 删掉这个账号（垃圾桶图标）
2. 重新「＋ WorkBuddy」添加一次

### Q8：所有账号积分都显示 0？

**积分是缓存值**，程序还没查过。点 **「全部刷新」** 即可。

> 这条很重要 —— 不刷新的话「优先积分」策略会因为大家都是 0 分而**退化成随机选**。

### Q9：签到失败？

常见原因：

- **已签到** —— 面板会显示"已签到"，视为成功，无影响
- **余额查询失败** —— 偶尔网络抖动，下次签到会恢复
- **登录失效** —— 账号会变红，需重新添加

### Q10：改了 `0.0.0.0` 之后安全吗？

**不安全，除非你改了 API-Key。**

默认 Key `WorkBuddy2API` 是公开的。对外监听时必须改成一个复杂的随机字符串。程序会弹窗警告你。

### Q11：端口 7863 被占用？

面板右栏「API 监听」改成别的端口（如 `7864`），立即生效。

### Q12：能同时在多台电脑用同一批账号吗？

**不建议。** 同一账号多处并发使用容易触发平台风控。要迁移就整机迁移（注意凭证加密限制，见 §10.1）。

### Q13：面板上账号太多，显示不下？

左栏账号列表**内部滚动**，不影响右栏设置。窗口高度是固定的 760×560。

### Q14：怎么确认它在正常工作？

1. 托盘图标在 = 程序在跑
2. 面板头部显示 `运行中` = HTTP 服务正常
3. 账号卡片有积分数字 = 凭证有效
4. 浏览器访问 `http://127.0.0.1:7863/healthz` 返回 `ok` = 服务健康

## 13. 卸载

1. 面板 → **退出程序**
2. 删除程序目录（exe 及 `config.json` / `auths/` / `data/`）
3. 如果开过开机自启，**先关掉开关再删目录**（否则注册表残留启动项）
   - 手动清理：`Win+R` → `regedit` → `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` → 删掉 workbuddy-wild 项
